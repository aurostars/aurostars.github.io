# 个人主页履历与项目详情精修设计

日期：2026-09-14  
状态：用户已确认设计方向，待规范复核

## 1. 目标

在不推翻现有 B1「平衡通透」视觉体系的前提下，提高首屏信息密度，强化教育与实习经历的可扫描性，并重组项目详情的信息顺序和图片展示方式。

本轮成功标准：

1. 桌面端履历区采用教育 36%、实习 64% 的非对称双栏布局。
2. 顶部身份卡与履历卡距离收紧，履历卡高度降低；常见桌面首屏至少露出“个人项目”标题。
3. 教育经历使用正式校徽和三行信息结构；实习经历使用官方公司图标和紧凑时间轴。
4. 项目详情删除“核心问题”，将“背景”和“目标”拆成两个独立整行模块。
5. 项目图片数量与布局按用户指定规则收敛，单图尽可能放大，双图充分利用空间。
6. 不破坏现有原生 dialog、URL 深链、History、键盘、Reduced Motion、无 JavaScript和图片失败降级能力。

## 2. 保持不变的设计基础

- 延续冰白/雾蓝背景、低饱和电蓝强调和克制磨砂表面。
- 保留现有身份栏中的姓名、邮箱和 GitHub。
- 保留整张项目卡片可点击、视口居中的原生项目 dialog。
- 保留功能列表、“查看源码”、图片 contain 展示和稳定失败回退。
- 移动端仍将教育和实习改为上下排列，不强行维持双栏。

## 3. 首屏与履历布局

### 3.1 垂直节奏

- 缩小身份卡与履历卡之间的垂直间距。
- 减少履历卡上下内边距、条目之间的间距和不必要的最小高度。
- 履历区不使用固定高度；内容决定高度。
- 在常见桌面视口中，首屏底部至少显示“个人项目”标题，提示页面仍有后续内容。

### 3.2 桌面比例

- 履历容器使用 CSS Grid。
- 教育列占 36%，实习列占 64%。
- 两列顶部对齐，间距沿用当前页面的紧凑节奏。
- 小于 768px 时改为单栏，教育在前、实习在后。

### 3.3 教育经历

采用参考图中的“校徽 + 三行信息”结构。每所学校为一个紧凑条目，校徽位于左侧，文本位于右侧：

1. 北京师范大学
   - 第二行：经济与工商管理学院　经济学　硕士
   - 第三行：2024 - 2027
2. 中国人民大学
   - 第二行：劳动人事学院　经济学　学士
   - 第三行：2020 - 2024

要求：

- 使用两所学校正式校徽的本地静态资源。
- 校徽完整显示，不裁切、不变色。
- 学校名使用较高字重；学院、专业、学位为次级正文；日期使用 tabular numbers。
- 日期继续使用语义化 `<time>`。
- 校徽加载失败时保留固定尺寸占位和完整学校名称，布局不得塌陷。

### 3.4 实习经历

实习区采用参考图中的紧凑纵向时间轴：

- 每条经历第一行依次放置：公司 Logo、公司名、职位、时间。
- 公司名和职位靠左，时间靠右；窄屏允许时间换至下一行，但不与正文混淆。
- 工作内容单独位于下一行。
- 所有文字继续使用正文黑色/深色主题正文色，不使用公司品牌色给文字着色。
- Logo 使用用户参考图所示的官方品牌图标，并以本地静态资源保存；不得使用字母占位替代正常状态。

文案变更：

- 美团快驴改为“美团”，工作内容改为“供应链质量管理”。
- 国务院发展研究中心大数据研究院的工作内容改为“大数据平台产品构建”。
- BOSS 直聘的工作内容改为“行业研究与产品优化”。
- 其他经历事实、时间和工作内容保持当前已确认版本。

## 4. 项目详情结构

### 4.1 顶部操作区

- dialog 左侧继续显示项目名称和一句简介。
- “查看源码”移动到右上角操作区，位于关闭按钮左侧。
- “查看源码”仍为唯一外部项目链接，并保留新窗口提示和安全 rel 属性。
- 关闭按钮在可点击状态下使用 `cursor: pointer`，同时保留清晰的 hover、active 和 focus-visible 状态。

### 4.2 内容顺序

详情滚动区按以下顺序展示：

1. 项目图片
2. 背景
3. 目标
4. 工作流程
5. 已实现功能

变化：

- 删除所有项目的“核心问题”标题与内容，不留空容器。
- “背景”和“目标”不再并排；每个模块单独占一整行。
- 已实现功能继续使用语义化列表。
- “查看源码”不再位于滚动内容末尾，而是固定在 header 右上角。

### 4.3 响应式与滚动

- header 操作区在桌面端单行显示；空间不足时允许源码链接和关闭按钮保持可点击，标题区域可收缩。
- dialog 保持视口居中、最大高度限制和内部滚动。
- 右上角操作区不得遮挡标题或简介。
- Reduced Motion 下不引入位移或缩放动画。

## 5. 项目图片策略

图片继续使用 `object-fit: contain`，不裁切产品界面；通过网格比例和容器尺寸放大，而不是强行 cover。

### 5.1 秋招网申助手

- 只保留两张图：扩展弹窗、个人信息设置页面。
- 第一张保持完整展示。
- 第二张扩大，宽度或高度尽可能占满第一张之外的剩余图片区。
- 桌面端优先采用主次双图布局：第二张获得更大面积；窄屏改为上下堆叠。

### 5.2 面试复盘助手

- 只保留第一张图。
- 图片在详情顶部使用最大可用宽度展示。

### 5.3 智能简历编辑工具

- 只保留第一张图。
- 图片使用最大可用宽度和合理高度，占满详情顶部图片区。
- 删除以下来源说明及其容器：
  - “基于 https://github.com/JOYCEQL/magic-resume 二次开发；当前仓库 README 明确列出的个人修改范围：扩展 API 提供商、增加主题色预设与模板、增加简历快速生成、JD 定制优化、STAR 法则改写、中英简历互译和多格式导出。”

### 5.4 智能会议纪要工具

- 只保留第一张图。
- 图片使用最大可用宽度展示。

### 5.5 失败降级

- 单图和双图布局都必须保留稳定比例的失败占位。
- 某张图失败不得导致 dialog 宽度、滚动或其他模块位置异常。

## 6. 内容与数据模型

- 教育数据需要增加学院和学位字段，并增加学校 Logo 元数据。
- 项目数据中的媒体数组按上述规则裁剪。
- 详情组件不再消费或渲染“核心问题”字段。
- 背景和目标仍分别保存在清晰字段中，不把两段文本拼接为一个字符串。
- 删除智能简历编辑工具的来源说明展示；若该字段仅服务于这段说明，应一并从渲染模型移除，避免死数据。

## 7. 组件边界

主要修改范围：

- `src/content/portfolio.ts`：教育、实习文案与项目媒体数据。
- `src/components/profile-history.tsx`：校徽教育结构、紧凑实习时间轴。
- 学校 Logo 组件：可复用现有 Logo 降级模式，避免重复故障逻辑。
- `src/components/case-dialog.tsx`：右上角源码链接与 header 布局。
- `src/components/case-detail.tsx`：删除核心问题、拆分背景/目标、媒体布局。
- `src/app/globals.css`：36/64 履历比例、紧凑间距、时间轴、dialog 操作区和单/双图布局。
- 相关 Vitest 与 Playwright 测试。

不进行框架迁移、路由重写、依赖升级或与本轮需求无关的视觉重构。

## 8. 无障碍与交互

- Logo 与项目图片提供准确 alt 文本。
- 关闭按钮保留可访问名称。
- “查看源码”保留可见焦点环。
- 履历信息顺序在 DOM 中与视觉阅读顺序一致。
- 项目详情的标题层级连续，删除“核心问题”后不得出现跳级。
- 鼠标 hover 出现手形只是增强，键盘操作必须保持完整。

## 9. 测试与验收

### 9.1 单元测试

- 两所教育经历逐字匹配，并验证学院、专业、学位、日期与 Logo。
- 实习经历验证公司名、职位、时间同行结构和三处新文案。
- 所有项目不再出现“核心问题”。
- 背景和目标分别为独立整行模块。
- “查看源码”位于 dialog header，且每个项目仅一个源码链接。
- 四个项目媒体数量分别符合：秋招网申助手 2 张，其余三个项目各 1 张。
- 智能简历编辑工具不再渲染指定来源说明。

### 9.2 浏览器测试

- 1440、1024、768px 下履历比例接近 36/64；两列不重叠。
- 767、390、320px 下履历上下排列且无横向溢出。
- 常见桌面首屏能看到“个人项目”标题。
- 学校校徽和公司 Logo 在浅色、深色主题均可辨识，资源失败时布局稳定。
- 关闭按钮 hover 的 computed cursor 为 pointer，键盘 focus-visible 可见。
- 源码链接位于 header 操作区且不遮挡标题。
- 单图项目图片明显放大并占据详情顶部可用宽度。
- 秋招网申助手双图布局在桌面端充分利用空间，在移动端正常堆叠。
- dialog 的居中、Escape、遮罩关闭、History、焦点恢复、Reduced Motion 均保持通过。

### 9.3 发布门禁

- 单元测试、Lint、Typecheck、完整 Chromium 测试、Reduced Motion、无 JavaScript、生产构建、依赖审计和 diff check 全部通过。
- 部署后检查所有校徽、公司 Logo 和项目图片，无破图、无明显空白、无控制台错误。
