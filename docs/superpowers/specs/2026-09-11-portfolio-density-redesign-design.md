# 个人作品集高密度改版设计规范

**日期：** 2026-09-11  
**状态：** 已确认，待实施  
**目标页面：** 董星个人作品集首页  
**主要受众：** AI 产品经理岗位招聘者

## 1. 背景与问题

当前版本采用明亮 Product Storyboard 视觉语言，项目资料完整，但更接近展览式长页。招聘者需要经历较长滚动距离才能完成四个案例的第一轮扫描。

已确认的问题包括：

- Hero 接近占满首屏，首屏信息量偏低。
- H1、案例区标题和案例标题字号过大。
- 四个案例全部纵向完整展开，每个案例拆分成简介、画廊、背景目标、核心问题、工作流程、能力和出处等多个区块。
- 案例之间存在最高约 160px 的纵向间距。
- 经历、教育、能力和联系继续以独立大区块排列，进一步拉长页面。
- 用户未来可能增加两个案例，现有纵向结构会随案例数量线性增长。

本次改版不改变已有内容真实性、案例范围、链接和视觉品牌，只重新组织信息层级、字号、间距与交互方式。

## 2. 设计目标

1. 让招聘者在 30 秒内识别个人定位、四个项目和核心能力。
2. 将整页长度相较当前版本缩短至少 50%。
3. 让四个案例摘要在约 1.5 个桌面视口内完成扫描。
4. 保留四个案例的背景、目标、五步流程、真实图片、GitHub 链接与项目归属信息。
5. 支持未来扩展到六个案例，无需修改网格组件或页面结构。
6. 保留当前明亮、克制、高级的 Product Storyboard 视觉语言。
7. 保持键盘、减少动态效果和无 JavaScript 场景下的内容可访问性。

## 3. 已确认方向

采用 **B 方案：2×2 案例摘要网格 + 当前页原位展开详情**。

当前四个案例在桌面端形成 2×2 网格。未来增加第 5、6 个案例时自动形成 2×3 网格。正式页面不提前显示空白占位卡。

全局设计参数调整为：

- `DESIGN_VARIANCE: 6`
- `MOTION_INTENSITY: 3`
- `VISUAL_DENSITY: 7`

## 4. 信息架构

页面按以下顺序组织：

1. 导航
2. 紧凑 Hero
3. 案例摘要网格
4. 当前选中案例的原位详情
5. 经历、教育、能力与联系的紧凑信息区
6. 页脚

保持现有导航标签与锚点：

- `#cases`
- `#experience`
- `#contact`

## 5. Hero 设计

### 5.1 内容

Hero 最多包含四层信息：

1. 身份标签：AI 产品经理 / 独立开发者
2. H1：从问题定义，到结果验证。
3. 一句价值说明
4. 单一 CTA：查看案例

继续使用真实项目图片构成右侧拼贴，但减少图片占用面积，不增加装饰标签或额外说明。

### 5.2 尺寸与密度

- 导航高度：64px 左右，不超过 72px。
- Hero 不再使用 `min-height: calc(100dvh - nav)`。
- 桌面 Hero 总高度目标：460-520px。
- 桌面 H1 上限：52px。
- 移动端 H1 目标：34-36px。
- CTA 必须在初始视口可见。
- 桌面 1440px 下，Hero 和第一排案例应在约两个视口内出现。

## 6. 案例摘要网格

### 6.1 网格规则

- 桌面端：两列。
- 移动端：单列。
- 当前四个案例：2×2。
- 未来六个案例：2×3。
- 网格严格按实际案例数量渲染，不使用空白占位单元格。

### 6.2 摘要卡内容

每张摘要卡仅显示：

- 一张主截图
- 项目名称
- 一句价值说明
- 三个能力关键词
- 展开状态指示
- 可直接访问的 GitHub 链接

摘要卡不显示完整背景、五步流程、完整图片组或长篇能力说明。

### 6.3 尺寸

- 项目名称：约 20-22px。
- 价值说明：15-16px，限制为简短段落。
- 卡片内边距：20-24px。
- 卡片间距：16-20px。
- 图片使用稳定比例并保留真实宽高信息，避免布局偏移。

## 7. 案例展开交互

### 7.1 桌面行为

- 点击摘要卡后，在该卡所在行的下方展开一块横跨两列的详情区域。
- 同一时间只允许一个案例展开。
- 点击已选中的案例或关闭控件可收起详情。
- 点击另一案例时，原详情收起，新详情在对应行下方展开。

### 7.2 移动端行为

- 详情直接出现在被点击卡片下方。
- 不产生横向滚动。
- 保持摘要卡与详情的视觉归属关系。

### 7.3 详情内容

详情集中展示：

- 项目名称与 GitHub 外链
- 背景、目标、核心问题
- 恰好五步工作流程
- 已实现能力
- 真实产品图片组
- 项目出处与贡献范围

布局规则：

- 背景、目标和核心问题使用紧凑并排布局。
- 五步流程在桌面端使用横向轨道，在移动端切换为纵向。
- 产品图片使用紧凑三图画廊；存在四张图片时采用一大三小或等价的非重复布局。
- GitHub 链接位于详情顶部，不要求用户滚动到底部。
- Resume Builder 必须继续显示上游仓库和当前仓库可验证的个人修改范围。
- 禁止新增未经验证的指标、效果数据或贡献描述。

## 8. 经历、教育、能力与联系

将当前独立大区块压缩为一个紧凑信息区域：

- 左侧或上部：五条单行实习经历。
- 右侧或下部：教育背景与五项核心能力。
- 联系方式作为该信息区域的收束部分。

约束：

- 每段实习仍严格保持一行，不恢复长描述。
- 联系方式只包含 `dongxing.123@bytedance.com` 与 `https://github.com/aurostars`。
- 不增加电话、微信、LinkedIn 或其他 CTA。
- 桌面端整体目标不超过一个视口；移动端自然堆叠。

## 9. 视觉系统

继续沿用现有明亮 Product Storyboard：

- 冷白背景、白色表面、银灰边框。
- 深石墨正文。
- 单一钴蓝强调色。
- Geist 字体。
- 统一圆角和焦点样式。
- 无渐变、无玻璃拟态、无外发光、无暗色插入区块。

字号上限与建议层级：

- H1：52px 桌面 / 34-36px 移动端。
- 一级区块标题：30-34px。
- 案例名称：20-22px。
- 正文：15-16px。
- 辅助信息：12-14px，但必须满足可读性与对比度要求。

间距规则：

- 一级区块间距：64-80px。
- 不再使用 100px 以上的常规案例间距。
- 卡片内部间距：20-24px。
- 展开详情内部按内容组使用 24-40px 的节奏。

## 10. 动效与可访问性

动效降至低强度，仅保留用于状态反馈的动画：

- 案例详情展开与收起。
- 卡片 hover、focus 和 active 状态。
- 链接与按钮反馈。

移除或减少：

- 大范围滚动 Reveal。
- 长延迟的分段入场。
- 与信息理解无关的自动动效。

可访问性要求：

- 摘要按钮使用 `aria-expanded`。
- 按钮通过 `aria-controls` 关联详情区域。
- 全部交互支持键盘操作。
- 焦点样式持续可见。
- `prefers-reduced-motion` 下立即切换状态，不执行展开动画。
- 服务端输出与无 JavaScript 场景至少保留四个案例摘要、核心说明、GitHub 链接和真实图片。

## 11. 组件边界

### Hero

负责紧凑首屏内容与项目拼贴，不管理案例状态。

### FeaturedCases

负责：

- 渲染任意数量的 `portfolioCases`。
- 管理当前展开的案例 `slug`。
- 保证最多展开一个详情。
- 按案例顺序插入正确的详情位置。

### CaseSummaryCard

负责单个案例摘要、外链和展开按钮，不直接包含完整详情。

### CaseDetail

负责背景、目标、核心问题、五步流程、能力、图库和出处。

### ProfileIndex

统一组合经历、教育、能力与联系，保持内部数据组件可独立测试。

数据继续由 `src/content/portfolio.ts` 提供。新增案例只需加入符合 `ProjectCase` 类型的数据和真实媒体，不应修改布局组件。

## 12. 状态与错误处理

页面不依赖远程业务数据，没有异步加载状态。

防御性约束：

- 缺少媒体时由现有媒体契约测试阻止合并。
- 案例数量为奇数时，最后一张卡自然占据一个网格单元，不创建空卡。
- 案例详情中的可选出处信息仅在存在时显示。
- 外链使用安全的新窗口属性。
- 展开状态只保存合法案例 `slug` 或 `null`。

## 13. 测试策略

采用 TDD，先增加失败测试，再修改实现。

必须覆盖：

1. Hero 不再依赖满视口高度，并维持单一 CTA。
2. 四个案例摘要全部出现且顺序正确。
3. 默认无完整案例详情展开。
4. 点击摘要后出现对应详情。
5. 同时最多存在一个展开详情。
6. 再次点击可收起。
7. `aria-expanded` 与 `aria-controls` 正确。
8. 每个详情仍包含背景、目标、恰好五步流程、真实媒体和 GitHub 链接。
9. 网格对新增第五、第六个数据项无需组件改动。
10. 联系区域仍只包含批准的邮箱和 GitHub。
11. 旧大范围 Reveal 不再应用于主要区块。

最终执行：

- `npm test`
- `npm run lint`
- `npm run typecheck`
- `npm run build`
- `git diff --check`

至少检查以下宽度：

- 1440px
- 1024px
- 768px
- 390px
- 320px

验收标准：

- 桌面 H1 不超过 52px。
- 320px 无横向滚动。
- Hero CTA 在首屏可见。
- 四个摘要可在约 1.5 个桌面视口内扫完。
- 整页默认收起状态长度相较当前线上预览减少至少 50%。
- 展开详情不会遮挡内容或导致错误滚动定位。
- 所有真实图片加载成功。
- 键盘可以打开、切换和关闭详情。
- reduced motion 下无展开动画。
- 控制台无运行时错误。

## 15. 非目标

本次不包括：

- 修改四个案例的事实内容或仓库范围。
- 新增虚构指标。
- 增加新的项目案例。
- 修改导航标签或 URL 路由。
- 引入新的 UI 框架或动画库。
- 增加暗色模式。
- 推送远端、创建 PR 或正式发布，除非用户后续明确要求。
