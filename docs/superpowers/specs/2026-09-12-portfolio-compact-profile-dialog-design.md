# 个人主页高密度档案式重构设计

**日期：** 2026-09-12  
**状态：** 已确认，待实现

## 设计判断

本轮将个人主页从“宣言式 Hero + 大型案例展开页”重构为一张面向招聘者快速扫描的个人档案页。页面只保留身份与联系方式、教育经历、实习经历、个人项目三类核心信息；通过紧凑排版和项目弹窗形成“先总览、再深入”的两层阅读体验。

- `DESIGN_VARIANCE: 5`
- `MOTION_INTENSITY: 4`
- `VISUAL_DENSITY: 8`
- 模式：Redesign - Restructure
- 视觉基础：保留现有 Geist 字体、浅色冷灰背景、蓝色强调色与克制圆角
- 目标页长：在 `1440 × 900` 桌面视口中，常规浏览约 1.5–2 个视口；移动端不受此高度目标约束
- “Redesign - Restructure”表示允许重排信息架构和组件边界，但保留品牌语言、内容事实、路由方式与既有数据源

## 目标

1. 删除大型 Hero、口号“认真体验，持续表达”、占屏 CTA 与装饰性首屏内容。
2. 让访客在短时间内完整看到教育、实习和全部项目总览。
3. 项目区域可自然容纳约 6 个项目，不因新增项目显著改变页面结构。
4. 点击项目后在当前页居中查看完整案例，不跳离上下文。
5. 保留现有高质量截图、项目详情数据、轻量卡片反馈与 reduced-motion 能力。

## 信息架构

页面按以下顺序组织：

1. 顶部身份条
2. 教育与实习经历
3. 个人项目总览
4. 项目详情弹窗（按需出现）

不设置侧边目录、顶部目录或页内项目锚点。页面本身不超过约两屏，额外导航会占用空间并制造不必要的复杂度。

## 个人项目总览

项目总览是页面的视觉中心。

### 网格

- 视口宽度 `≥1080px`：3 列，6 个项目形成稳定的 `3 × 2`。
- 视口宽度 `680–1079px`：2 列。
- 视口宽度 `<680px`：1 列。
- 网格使用等宽轨道，最大列数为 3；卡片最小可读宽度约 `280px`。
- 4 或 5 个项目时，末行保持同一列宽并从行首排列，不跨列放大、不拉伸填满。
- 当前数据中已有 4 个项目；实现必须按数据自动排布，并为未来第 5、6 个项目直接扩展，不展示空白占位或虚构项目。

### 卡片内容

每张卡片只保留用于快速判断的信息，并将整张卡片实现为单一原生 `<button type="button">` 弹窗触发器：

1. 16:9 真实产品截图
2. 项目名称
3. 一句话简介
4. 类型、关键词或年份等轻量元信息
5. 位于同一按钮内部的“查看详情”视觉提示

卡片内部不嵌套第二个按钮或链接，源码链接仅出现在详情弹窗中。原生按钮负责 Enter/Space 行为并保留清晰的键盘焦点状态。

### 截图规则

- 卡片缩略图具有固定 `aspect-ratio: 16 / 9` 和固有尺寸占位，避免 CLS。
- 产品界面截图默认使用 `object-fit: contain` 与中性底色，不能裁掉关键 UI；仅对确认可安全裁切的封面使用 `cover`。
- 每张信息性截图使用描述“项目名 + 界面/状态”的有效 alt 文本，不重复卡片标题；纯装饰背景图使用空 alt。
- 首行可见缩略图正常加载，其余缩略图和弹窗画廊延迟加载；弹窗首张图在打开对应项目后优先加载。
- 加载失败时显示保持 16:9 占位的文字回退，不展示破图图标。

### 视觉密度

- 卡片图片高度统一，避免源图比例造成网格跳动。
- 项目名称完整可见，不能依赖 tooltip；简介在桌面最多 2 行、移动端最多 3 行，超出时一致截断，完整简介仍可在弹窗中读取。
- 卡片间距明显小于当前版本，但不牺牲触控尺寸。
- 使用细分隔线和真实截图建立层级，不依赖厚阴影、大面积渐变或装饰性编号。

## 居中项目详情弹窗

点击任意项目卡片后，在当前页面上方打开居中详情弹窗。

### 桌面行为

- 弹窗宽度约为视口的 `70–76%`，最大宽度 `1100px`。
- 弹窗与视口上下至少保留 `24px`，最大高度为 `calc(100dvh - 48px)`。
- 只有弹窗正文容器滚动；遮罩和弹窗外框固定，关闭按钮始终可见且拥有独立占位，不覆盖标题。
- 页面背景轻微压暗和模糊，但项目总览仍隐约可辨；滚动条锁定时补偿其宽度，避免页面横向跳动。
- 弹窗内容复用现有项目详情数据：背景与目标、个人贡献、工作流程、产品截图、来源说明和源码链接。

### 移动端行为

- `<680px` 时使用视口四周约 `8px` 的近全屏面板，宽度为 `calc(100% - 16px)`，最大高度为 `calc(100dvh - 16px)`。
- 使用 `dvh` 适应移动浏览器地址栏与横竖屏变化，并通过 `env(safe-area-inset-*)` 为安全区增加内边距。
- 弹窗标题栏保持 sticky，关闭按钮始终可见并不遮挡标题；仅正文区域垂直滚动。
- 不出现横向滚动，图片按单列阅读；软键盘出现时仍能访问关闭按钮。

### 打开与关闭

- 点击卡片打开对应详情；弹窗采用原生 `<dialog>.showModal()`，由浏览器提供背景 inert 与基础焦点约束，并补充一致的焦点循环测试。
- 初始焦点落在弹窗标题栏的关闭按钮；标题使用 `<h2 id="case-dialog-title">` 并由 `aria-labelledby` 关联。
- 支持关闭按钮、点击遮罩和 `Escape` 关闭。遮罩仅在 pointer down/up 都发生于遮罩本身时关闭，避免拖动或选中文本时误触。
- 打开时锁定页面背景滚动，弹窗正文独立滚动。
- 从卡片打开时，关闭后将焦点返回原项目按钮。
- 通过深链接打开或原按钮已不存在时，关闭后将焦点移至项目区标题；该标题设置 `tabindex="-1"` 作为程序化回退焦点。
- 同一时间只存在一个项目详情。
- 弹窗中的外部链接保留可见焦点；若新窗口打开，链接文本或可访问名称必须明确提示。

### URL 状态

统一使用查询参数 `?project=<slug>`，不使用 hash。

| 操作 | URL / History 行为 |
| --- | --- |
| 从总览卡片打开 | `pushState` 写入项目参数，并在 `history.state` 标记为本页创建的弹窗记录 |
| 关闭由总览打开的弹窗 | 调用 `history.back()` 回到打开前的同页 URL |
| 直接访问有效项目 URL 后关闭 | `replaceState` 移除项目参数并停留在总览页 |
| 浏览器前进 / 后退 | 根据当前参数同步打开或关闭弹窗，不重置背景页面滚动位置 |
| 无效项目 slug | `replaceState` 清理无效参数，显示总览页且不报错 |

本轮不提供弹窗内“上一个 / 下一个项目”切换；访客关闭后从总览选择另一项目，避免额外导航和历史记录歧义。

## 动效策略

复用现有 Motion 原语，但降低整体动效强度以适配更高密度布局。

### 页面进入

- 身份条、履历区和项目区分别进行一次轻量 `opacity + y` 进入。
- 不为每一行经历制造明显的长错峰。
- 不改变页面初始布局，不产生内容闪烁。

### 项目卡片

- 精细指针设备保留轻微倾斜和局部高光，必须同时满足 `(hover: hover)` 与 `(pointer: fine)`。
- 最大倾斜幅度从现有 `3deg` 收敛到约 `2deg`。
- 悬停上移不超过 `3px`。
- 高光不得降低正文或焦点环对比度，且始终为 `pointer-events: none`。
- 触屏设备保持静态卡片。

### 弹窗

- 遮罩与弹窗只动画 `transform` 和 `opacity`。
- 遮罩使用短淡入淡出。
- 弹窗使用轻微缩放与上移进入，退出方向相反。
- 不使用弹簧过冲、翻转或复杂景深。
- 本轮没有弹窗内项目切换；每次只打开一个项目。

### Reduced Motion

当 `prefers-reduced-motion: reduce` 时：

- 页面内容直接显示最终状态。
- 卡片倾斜和高光停用。
- 弹窗立即打开和关闭。
- 页面功能、焦点顺序和 URL 状态保持不变。

## 组件架构

建议将现有组件调整为以下职责：

1. `IdentityBar`：替代当前 `Hero`，负责姓名、职业定位和联系方式。
2. `ProfileHistory`：由 `HeroProfileIndex` 演化而来，独立展示教育与实习。
3. `FeaturedCases`：只负责项目网格与当前选中项目状态。
4. `CaseSummaryCard`：压缩为适合 3 列网格的项目摘要卡。
5. `CaseDialog`：新的无障碍详情弹窗容器。
6. `CaseDetail`：继续负责项目详情内容，去除对原位展开布局的假设。

项目数据继续由 `src/content/portfolio.ts` 提供。UI 通过数组长度自动排布，不硬编码 4 或 6 个项目。

## 可访问性

弹窗采用原生 `<dialog>` 的隐式 dialog 语义，并满足以下要求：

- `showModal()` 建立模态上下文，标题通过 `aria-labelledby="case-dialog-title"` 与唯一 `<h2>` 关联。
- 初始焦点落在关闭按钮，Tab/Shift+Tab 不逃逸到背景页面。
- 浏览器通过模态 dialog 使背景 inert；额外的滚动锁定不能破坏辅助技术访问。
- 从卡片打开时关闭后返回原按钮；深链接或触发器缺失时回到项目区标题。
- 卡片使用单一原生按钮打开，关闭按钮有明确文本标签。
- 弹窗长正文拥有清晰滚动边界，初始聚焦关闭按钮不会令正文跳到中段。
- 所有交互保持可见的 `:focus-visible` 样式。

## 响应式约束

需至少验证以下视口：

- `1440 × 900`：3×2 项目网格，常规页面约 1.5–2 屏。
- `1024 × 768`：2 列项目网格，不压缩文字。
- `768 × 900`：2 列网格，弹窗接近全宽。
- `390 × 844` 与 `320 × 800`：单列网格、近全屏详情、无水平滚动。
- 额外验证 200% 与 400% 页面缩放、浏览器文字放大，以及 320px 下长邮箱与长项目名。

页面不使用横向滚动、sticky 侧栏、滚动劫持或隐藏式桌面专属导航。
